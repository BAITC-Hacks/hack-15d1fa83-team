# Инструментарий создания моделей

[English version](README.en.md) · [Сервис и интеграция](../README.ru.md)

## Назначение и отделение от сервиса

Эта папка — отдельная точка входа для создания и оценки следующих моделей. Сервер прогнозирования никогда не запускает её автоматически. Команды вызывают общий код данных/признаков/обучения и существующие контроллеры. Подготовка признаков имеет одну реализацию, общую для обучения и инференса.

Все команды ниже выполняются из **корня репозитория**. Относительные пути считаются от текущей рабочей папки. Пути с пробелами заключайте в кавычки. `YOUR_INSTANCE` и `JOB_ID` — обозначения вашего реального инстанса Brev и квитанции, напечатанной при отправке задания; это не входы погодной модели.

```bash
python training_toolkit/run.py --help
python training_toolkit/run.py train --help
python training_toolkit/run.py auto --help
python training_toolkit/run.py brev --help
```

| Команда | Что выполняет | Локальные требования |
|---|---|---|
| `fetch` | Скачивание архива JMA по обеим точкам | Установленный корневой пакет |
| `assemble` | Объединение погоды и часовой мощности | Установленный корневой пакет |
| `train` | Обучение/экспорт нейросети с MSE | Пакет с extra `train`; CUDA при выборе GPU |
| `auto` | Отправка/возобновление, контроль, загрузка/проверка, необязательный старт/стоп Brev | Стандартный Python и авторизованный Brev CLI |
| `brev` | Ручные submit/status/download | Стандартный Python и авторизованный Brev CLI |
| `benchmark` | Фиксированное CPU-сравнение моделей и функций потерь | Пакет с `train,benchmark` |
| `verify` | Независимая проверка экспорта и прямого API | Корневой пакет; GPU/PyTorch не нужны |

Для проверки уже работающего сервиса используйте `inference/smoke_test.py`: достаточно стандартного Python и включённых контрольных примеров.

## 1. Окружения

Для подготовки данных и проверки экспорта достаточно runtime-установки из основного README. На машине, которая будет непосредственно обучать модели:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[train,test,benchmark]'
```

Для Windows/CPU используйте `py -3.12 -m venv .venv`, а вместо `python` — `.\.venv\Scripts\python.exe`; активация необязательна. Для управления Brev с Windows запускайте контроллер в WSL под пользователем, у которого настроен Brev login. PyTorch на локальном компьютере-контроллере не требуется: он устанавливается и используется на удалённом worker.

Текущий релиз обучен на Brev H200 с Python 3.12.3, PyTorch 2.14.0+cu130, NumPy 2.5.3 и pandas 2.3.3. Полный список есть в `models/production/metrics.json`. Совместимость CUDA зависит от драйвера и сборки на worker; проверяйте её там. Другие версии/устройства могут дать другие веса при том же seed. Точный эталон интеграции — включённый в Git артефакт.

## 2. Входные данные и запреты на утечки

Получите у организаторов исходные CSV турбины 1 и турбины 2. Рабочие данные можно разместить в игнорируемой папке `data/`:

```text
data/turbine_1.csv
data/turbine_2.csv
data/weather.csv
data/training.csv
data/training.metadata.json
```

Собранный CSV и его metadata должны храниться вместе. Metadata содержит SHA-256 точных байтов CSV. Ручное изменение CSV без пересборки нарушает контроль целостности.

Обязательные колонки исходных измерений: `Статистическое время` и `Нормализованная активная мощность`. В CSV также есть фактический ветер и температура, но их нельзя подставлять вместо погодного прогноза. Исходные измерения не включены в Git. Несмотря на февраль в названиях исходных файлов, предоставленные данные фактически заканчиваются 31 января 2026 года.

Не обучайтесь на февральских целях. Не подменяйте архивные прогнозы реанализом или фактической будущей погодой. Архив с фиксированным смещением и архив точных выпусков — разные продукты; добавление поля времени не создаёт отсутствующую информацию о публикации.

## 3. Скачивание архива погоды

```bash
python training_toolkit/run.py fetch --start 2023-03-10 --end 2026-01-31 --output data/weather.csv
```

Загрузчик обращается по обеим сохранённым координатам за JMA GSM, ветром на 10 м и температурой на 2 м, используя смещения провайдера 1 и 2. Единицы — м/с и °C, время UTC. Дополнительный день 10 марта UTC покрывает начало измерений 11 марта по местному времени. Запросы выполняются помесячно; сжатые ответы и сведения о запросах/хешах кэшируются в папке кэша рядом с погодным выходом. Перед повторным использованием кэш проверяется. `weather.manifest.json` содержит происхождение запросов и количество пропусков.

Команда требует сети; действуют ограничения и доступность провайдера. Пропуски учитываются, а не превращаются в нули. Исходный временной шаг JMA GSM грубее часового интерполированного результата. Семантика записывается как `provider_fixed_offset_not_exact_issue_time`: эти данные сами по себе не доказывают, какой именно выпуск модели был доступен в конкретный исторический момент.

## 4. Сборка датасета двух турбин

```bash
python training_toolkit/run.py assemble \
  --weather data/weather.csv \
  --turbine turbine_1=data/turbine_1.csv \
  --turbine turbine_2=data/turbine_2.csv \
  --measurement-timezone Asia/Almaty \
  --timestamp-position start \
  --output data/training.csv
```

Для PowerShell пишите команду в одну строку или используйте его собственный перенос строк; Bash-символ `\` не является переносом PowerShell. Если в пути есть пробелы, заключите целиком аргумент вида `turbine_1=ПУТЬ С ПРОБЕЛАМИ.csv` в кавычки.

`Asia/Almaty` учитывает исторический переход UTC+6 → UTC+5. Постоянное UTC+5 на весь период для этой интерпретации неверно. Неоднозначные метки исключаются и считаются. Сборщик отклоняет дубли времени, требует шесть десятиминутных измерений для часового среднего, связывает каждую турбину с её погодной точкой, исключает пропуски необходимых погодных полей и цели начиная с 2026-02-01 UTC.

Сейчас `--timestamp-position start` — предположение. Если организаторы подтвердят конец интервала, соберите данные с `end`, переобучите и переоцените модель. Добавляйте `--alignment-confirmed` только после подтверждения временных соглашений. Нельзя просто изменить флаг у старого артефакта без исправления и проверки данных.

Текущий датасет содержит 96 900 строк и 48 450 пар «турбина–час». Повторная загрузка архива или исправленные CSV могут изменить количество строк и хеш. Сохраняйте новый аудит, не заявляя побайтовую идентичность без проверки.

## 5. Обучение непосредственно на выбранной машине

### CUDA worker

```bash
python -m pip install -e '.[train]'
python -c "import torch; print(torch.__version__, torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
python training_toolkit/run.py train --dataset data/training.csv --output-dir artifacts/candidate-01 --device cuda --epochs 80
```

Если GPU недоступен, CUDA-режим завершится ошибкой, а не скрыто перейдёт на CPU.

### Явное обучение на локальном CPU

```bash
python training_toolkit/run.py train --dataset data/training.csv --output-dir artifacts/candidate-cpu --device cpu --epochs 80
```

Базовая сеть небольшая: сравнение на реальных данных уже выполнялось локально на двух CPU-потоках. Используйте GPU, когда объём работы это оправдывает; для сервиса он не требуется. Команда `train` ограничивает CPU-потоки PyTorch двумя. Не сохраняйте эксперимент сразу в `models/production/`.

Настройки по умолчанию: seed 42, batch 512, AdamW с learning rate 0.002 и weight decay 0.001, слои 64/32 с ReLU, sigmoid на выходе, MSE. Максимум 80 эпох, patience 10, лучший checkpoint по validation MAE. Обучение до октября 2025, validation — октябрь–декабрь, оценка — январь. Границы можно задавать параметрами из `train --help`, сохраняя временное разделение и исключение февральских целей.

| Файл результата | Содержимое |
|---|---|
| `model.json` | Веса, нормализация, схема признаков, турбины/источник, происхождение датасета |
| `metrics.json` | Версии, seed, разбиение, история, MAE/RMSE/bias, baseline и метрики по турбинам/смещениям |
| `evaluation_predictions.csv` | Январские цели/прогнозы для независимой проверки |

Перед успешным завершением trainer загружает экспортированную переносимую модель и сравнивает её с PyTorch. Постоянный прогноз и ветровая кривая рассчитываются только по обучающим целям. Строки разных архивных смещений не являются независимыми наблюдениями мощности.

## 6. Автоматический процесс NVIDIA Brev

Brev предоставляет GPU-инстансы. Кредит/купон аккаунта не является API инференса или ключом авторизации. Используйте существующий разрешённый инстанс. Контроллер не создаёт новый инстанс и не активирует купон.

Установите официальный Brev CLI по актуальной инструкции NVIDIA, затем в авторизованной Linux/WSL-сессии:

```bash
brev login
brev list
brev refresh
```

Выберите **точное имя существующего инстанса** из списка. В предыдущих запусках проекта использовалось `wind-training`. Типовой следующий запуск:

```bash
python3 training_toolkit/run.py auto \
  --instance YOUR_INSTANCE \
  --dataset data/training.csv \
  --output-dir artifacts/brev-candidate-01 \
  --epochs 80 --start-instance --stop-instance
```

Оставьте терминал контроллера открытым. Старт остановленного GPU возобновляет оплату вычислений. Контроллер сначала проверяет завершённые результаты и существующие задания, ждёт GPU/SSH, отправляет задание один раз, следит за обучением, скачивает и проверяет результаты и только затем запрашивает остановку инстанса. После настройки авторизации штатный запуск не требует ввода команд или паролей.

Если датасет, инстанс и запрошенное число эпох совпадают с существующим отправленным заданием, повторный запуск возобновляет наблюдение. Завершённое задание не обучается заново. Для новых настроек используйте новую папку результата; не стирайте квитанции, чтобы принудительно повторить запуск. Контроллер хранит `progress.log`, OS-блокировку `automation.guard`, квитанции в `jobs/`, `results.zip`, извлечённые результаты и `complete.json`. Само наличие guard-файла не означает активной блокировки: ОС освобождает её после завершения процесса. Не удаляйте активный guard вручную.

Старый пустой `automation.lock` удаляется только после проверки отсутствия соответствующего старого процесса. Если открыто другое окно обучения, закройте прежний локальный контроллер и повторите запуск. Закрытие наблюдателя не предназначено для отмены удалённого detached-обучения. Прерванная отправка с `submitted: false` требует проверки: удалённая операция могла частично выполниться, поэтому автоматическое дублирование запрещено.

При ошибках и тайм-аутах смотрите `progress.log` и консоль Brev. GPU не останавливается автоматически при каждой ошибке: обучение может ещё выполняться. Проверяйте состояние и оплату, прежде чем оставить его без работы. Наблюдение по умолчанию ограничено 90 минутами; позднее можно возобновить существующее задание. Ожидание CLI status/start/stop ограничено по времени. Старт использует `--detached`; переход из остановленного состояния ещё требует отдельной живой проверки, хотя совместный submit/download/stop уже успешно выполнен.

### Ручные операции

```bash
# Только собрать архив, не выполнять удалённые команды:
python3 training_toolkit/run.py brev submit --instance YOUR_INSTANCE --dataset data/training.csv --prepare-only

# Отправить новое задание на уже работающий GPU:
python3 training_toolkit/run.py brev submit --instance YOUR_INSTANCE --dataset data/training.csv --epochs 80

# Использовать точный путь квитанции, напечатанный при отправке:
python3 training_toolkit/run.py brev status --job artifacts/brev-jobs/JOB_ID/job.json
python3 training_toolkit/run.py brev download --job artifacts/brev-jobs/JOB_ID/job.json --output artifacts/download/results.zip
```

Ручной download получает ZIP, но не заменяет модель сервиса и не останавливает инстанс автоматически. Автоматический процесс выполняет проверку, извлечение и необязательную остановку. `--prepare-only` не отправляет задание; такую квитанцию нельзя выдавать за успешное обучение или помещать в каталог авто-возобновления как завершённое задание.

### Ошибка удалённого venv

Если worker сообщает об отсутствии `ensurepip` на использованном образе Ubuntu/Python 3.12:

```bash
brev exec YOUR_INSTANCE "sudo apt-get update && sudo apt-get install -y --no-install-recommends python3.12-venv"
```

Пакет устанавливается на удалённый worker, не на Windows-компьютер. Для другого Python подберите соответствующий пакет venv. Первичная авторизация/sudo может потребовать действий владельца аккаунта; пароли не должны попадать в код или квитанции.

## 7. Сравнение кандидатов

```bash
python -m pip install -e '.[train,benchmark]'
python training_toolkit/run.py benchmark --dataset data/training.csv --baseline models/production/model.json --output artifacts/comparison-01
```

Каталог результата должен быть новым. До обучения фиксируется список кандидатов: CPU-сети с MSE/MAE/Huber, более крупная сеть, другой seed, общие/раздельные варианты CatBoost и два фиксированных ансамбля. Выбор производится по октябрю–декабрю, записывается `selection.json`, затем считается январь. Январь уже просматривался ранее: в этом эксперименте он исключён из обучения и выбора, но не является полностью слепым внешним тестом.

Сохраняются протокол, версии пакетов, модели кандидатов, validation-прогнозы, полные январские прогнозы, оценки по турбинам/смещениям, JSON/CSV сравнения и bootstrap по дням. Последний приближённо описывает неопределённость внутри месяца и не доказывает улучшения в другом сезоне. Запуск сравнения никогда не заменяет текущий релиз.

Фактические результаты находятся в `docs/MODEL_COMPARISON.md`: выбранный по MAE ансамбль уменьшает среднюю абсолютную ошибку, но увеличивает RMSE. По пожеланию пользователя этот релиз сохраняет исходную MSE-сеть с меньшим вкладом крупных ошибок. В следующих экспериментах метрику выбора нужно фиксировать заранее и использовать validation, а не выбирать удачный январский результат постфактум.

## 8. Проверка и выпуск кандидата

```bash
python training_toolkit/run.py verify --dataset data/training.csv --results artifacts/candidate-01
```

Проверяются хеш датасета, полное покрытие тестовой части, соответствие целей, переносимые прогнозы, общие/потурбинные метрики и оба API-пути на 48 часов. Записываются независимый отчёт и контрольные запросы/ответы. Provisional-артефакты разрешаются явно внутри проверки, но их статус не скрывается. Текущий verifier рассчитан на экспорт MLP; для CatBoost или ансамбля нужен адаптер инференса до замены артефакта сервиса.

Выпуск — отдельное проверяемое действие:

1. Зафиксировать правило выбора по validation, MAE/RMSE/bias и результаты обеих турбин.
2. Подтвердить источник, единицы, координаты и время; сохранить реальные ограничения в metadata.
3. Независимо проверить кандидата и сохранить прежний артефакт для отката.
4. Перенести выбранную модель и отчёты в `models/production/`, одновременно обновить хеш/версию manifest и контрольные ответы.
5. Выполнить регрессионные тесты и настоящий HTTP smoke test в окружении только с runtime.
6. Закоммитить релиз, перезапустить сервис, проверить metadata и сбросить кэш старой версии.

Нельзя выпускать другой артефакт под старой версией только переименованием. Нельзя ставить `alignment_confirmed: true`, чтобы убрать проверку старта. CUDA-обучение, локальная проверка и соответствие правилам исторического replay — разные проверки.
