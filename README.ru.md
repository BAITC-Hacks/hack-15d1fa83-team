# Прогноз мощности ВЭС: интеграция и эксплуатация

[English version](README.en.md) · [Инструментарий обучения](training_toolkit/README.ru.md) · [Точный контракт API](docs/ML_SERVICE_CONTRACT.md)

## 1. Что находится в репозитории

Это компонент команды для преобразования прогноза погоды в прогноз мощности: нейросеть, обученная с нуля, её веса, HTTP-сервис для CPU, примеры запросов для обеих турбин, тесты и отдельный инструментарий создания моделей. Компонент подготовлен для подключения и проверки другим разработчиком. Репозиторий не является публичным адресом работающего API и не содержит весь интерфейс или агента команды.

Выбранная модель — **`mlp-76540e5972a6`**. Веса уже включены в Git: [`models/production/model.json`](models/production/model.json). После клонирования отдельная загрузка весов не нужна. Исходные CSV измерений турбин, ключи NVIDIA, сервисные токены, платёжные купоны и локальные данные авторизации в Git не включены.

Модель поддерживает **обе турбины** и погодный источник **JMA GSM**. Выход — нормализованная мощность, а не энергия и не МВт. Для прогнозирования не нужны GPU, PyTorch, CatBoost, Brev, LLM или доступ к погодному API. Запуск сервиса и запрос прогноза не запускают обучение.

### Готовность и ограничения

- Совместное обучение на CUDA завершено. Экспортированная CPU-модель воспроизвела все 2 956 январских прогнозов с максимальным расхождением около 1,82e-7.
- Для обеих турбин есть контрольные примеры с реальной архивной погодой и исполняемая проверка HTTP-сервиса.
- Временные метки измерений интерпретируются в `Asia/Almaty` с историческим изменением UTC-смещения. Пока не подтверждено, означает ли метка начало или конец десятиминутного интервала. Сейчас принято **начало**.
- Поэтому `alignment_confirmed` равен **false**. Запуск требует явного флага `--allow-provisional` или `ALLOW_PROVISIONAL_MODEL=1`. Этот статус передаётся в ответах.
- Архивы с фиксированным смещением провайдера не подтверждают точное время выпуска/публикации каждого прогноза. Полная проверяемость исторического replay для конкурса пока не обеспечена.
- Предоставленные измерения заканчиваются 31 января 2026 года. Февральских целевых значений нет, поэтому точность на феврале не заявляется.
- Ещё нужна совместная проверка с реальным Django-сервисом другой части команды. Сборка и запуск Docker здесь не проверены: Docker Engine недоступен. Выполненные проверки описаны в [`reports/release_verification.json`](reports/release_verification.json).

## 3. Быстрый запуск: Python 3.12, только CPU

Команды выполняются из корня репозитория. Для проверенного набора зависимостей используйте **Python 3.12**. Пакет объявляет поддержку Python >=3.11, но конкретные версии зависимостей релиза проверялись с 3.12.

### Linux, macOS или WSL

```bash
git clone --branch feature/wind-power-baseline https://github.com/BAITC-Hacks/hack-15d1fa83-team.git
cd hack-15d1fa83-team
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-runtime.txt .
python inference/serve.py --allow-provisional
```

Для приватного репозитория нужен собственный доступ GitHub. Если проект уже клонирован, используйте существующую копию нужной ветки. Не записывайте GitHub-токен в команды, попадающие в репозиторий.

### Windows PowerShell: WSL для сервиса не нужен

```powershell
git clone --branch feature/wind-power-baseline https://github.com/BAITC-Hacks/hack-15d1fa83-team.git
```

Прямой вызов Python из venv не требует изменения политики выполнения PowerShell. WSL используется для проверенного сценария Brev CLI, но не для CPU-инференса.

Адрес по умолчанию — **http://127.0.0.1:8001**. Терминал нужно оставить открытым; остановка — Ctrl+C. `/docs` открывает интерактивную документацию API, `/health` сообщает готовность. Запускатель находит включённую модель относительно репозитория; вручную задавать `MODEL_PATH` не нужно.

### Проверка работающего сервиса

Во втором терминале, из того же репозитория и окружения:

```bash
python inference/smoke_test.py --url http://127.0.0.1:8001
```

PowerShell:

```powershell
.\.venv\Scripts\python.exe inference\smoke_test.py --url http://127.0.0.1:8001
```

Проверка отправляет два архивных запроса на 48 часов, сравнивает версию модели, временные метки и численные ответы, повторяет запросы и проверяет отказ при неполном горизонте или неверном погодном источнике. Если задан `ML_SERVICE_TOKEN`, проверяется и авторизация. При ошибке процесс завершается с ненулевым кодом. Эти файлы — контрольные исторические примеры, а не прогноз текущей погоды.

## 4. Настройки развёртывания

| Переменная | Назначение |
|---|---|
| `MODEL_PATH` | Необязательный путь к другой модели. При прямом запуске Uvicorn путь по умолчанию — `models/production/model.json` относительно рабочей папки; `inference/serve.py` использует путь репозитория. |
| `ALLOW_PROVISIONAL_MODEL` | `1` явно разрешает неподтверждённую временную привязку; по умолчанию `0`. |
| `ML_SERVICE_TOKEN` | Общий Bearer-токен Django и ML. Пустое значение отключает авторизацию для локальной разработки. |
| `WEATHER_PROVIDER_URL` | Только старый маршрут `/power/forecast`; для прямого инференса не задаётся. |
| `WEATHER_PROVIDER_TOKEN` | Токен старого погодного endpoint; это не ключ NVIDIA. |
| `WEATHER_TIMEOUT_SECONDS` | Тайм-аут старого погодного запроса, по умолчанию 15 секунд. |
| `ALLOW_HISTORICAL_FORECASTS` | Только старый маршрут; не влияет на `/v1/predict`. |

Приложение **не читает `.env` автоматически**. Передавайте переменные окружения через терминал, менеджер процессов или Compose. Имена настроек перечислены в `.env.example`. Общий токен выбирает команда; ключ Brev здесь не используется.

Для авторизации задайте одинаковое секретное значение в обоих процессах. Linux: `export ML_SERVICE_TOKEN='your-private-token'`. PowerShell: `$env:ML_SERVICE_TOKEN='your-private-token'`. В терминале контрольного HTTP-теста должно быть такое же значение. Настоящий токен нельзя коммитить.

Для другой машины или контейнерной сети используйте `--host 0.0.0.0 --port 8000`, включите авторизацию и настройте сеть/reverse proxy. `0.0.0.0` — адрес привязки процесса, а не адрес назначения для Django. Для публичного сетевого доступа используйте HTTPS на reverse proxy.

### Docker Compose

```bash
docker compose up --build -d
docker compose logs -f windpower-ml
python inference/smoke_test.py --url http://127.0.0.1:8001
# Остановить и удалить контейнер сервиса:

```

Образ включает выбранные веса и зависимости инференса, работает от непривилегированного пользователя и не обучает модель. Если Django находится в той же Compose-сети, используйте `http://windpower-ml:8000/v1/predict`. Для Django непосредственно на хосте — `http://127.0.0.1:8001/v1/predict`. Localhost внутри контейнера Django указывает на сам контейнер Django. Выбирайте адрес с учётом размещения процессов. Запуск с реальным Docker Engine здесь не проверялся.

## 5. Поток запросов и ответственность компонентов

```text
Пользователь / расписание -> Django-агент -> погодный модуль
                         -> сохранение погодного снимка в Django
                         -> POST /v1/predict отдельно для каждой турбины
                         -> проверка/сохранение ответа -> интерфейс
```

Погодная часть выбирает текущее или историческое время, получает прогноз по правильным координатам, проверяет его доступность в момент принятия решения и сохраняет происхождение данных. ML принимает готовую погоду, проверяет её структуру и возвращает мощность с версией модели. ML не получает latest forecast, не выдумывает issue time, не опрашивает обновления, не назначает повторные расчёты и не хранит прогнозы команды.

Новый погодный снимок или новая модель — причина нового вызова из Django. Кэшируйте по ID турбины, хешу канонического погодного снимка и фактической версии модели. Одинаковые входы и веса дают одинаковый ответ; запрос инференса не имеет записывающих побочных эффектов.

| ID турбины | Широта | Долгота |
|---|---:|---:|
| `turbine_1` | 43.645150 | 78.535604 |
| `turbine_2` | 43.643198 | 78.538828 |

Используйте координаты и ID именно нужной турбины. Близкие точки могут попадать в одну ячейку погодной сетки, но история мощности и признаки турбин остаются различными. Нельзя копировать прогноз мощности одной турбины как результат другой.

## 6. HTTP-интерфейс

| Endpoint | Назначение | Авторизация, если включена |
|---|---|---|
| `GET /health` | Готовность и версия загруженной модели | Нет |
| `GET /v1/metadata` | Турбины, источник, единицы, координаты, alignment | Да |
| `POST /v1/predict` | Подготовленная погода → мощность | Да |
| `GET /docs`, `GET /openapi.json` | Документация API | Нет |
| `POST /power/forecast` | Старый необязательный маршрут с получением погоды; не основной путь интеграции | Да |

В запросе ровно четыре поля верхнего уровня:

| Поле | Значение |
|---|---|
| `schema_version` | Строго `windpower.input.v1` |
| `turbine_id` | `turbine_1` или `turbine_2` |
| `weather_model` | Для этих весов строго `jma_gsm` |
| `records` | Ровно 48 последовательных записей с шагом один час |

Каждая запись содержит ровно:

| Поле | Единицы и ограничения |
|---|---|
| `target_time` | ISO 8601 с явным часовым поясом, целый UTC-час; предпочтительно `Z`. Смещение явно переводится в UTC. |
| `wind_speed_10m_ms` | JSON-число, 0..100, м/с на высоте 10 м |
| `wind_direction_10m_deg` | JSON-число, 0..360; метеорологическое направление ОТКУДА дует ветер, по часовой стрелке от севера, на высоте 10 м |
| `temperature_2m_c` | JSON-число, -100..70, °C на высоте 2 м |

Null, boolean, числа в строках, NaN/Infinity, пропуски, дубликаты, неправильный порядок часов и неизвестные поля отклоняются. Пределы значений служат проверкой входов, а не гарантией точности в экстремальных условиях. Давление, ветер на 100 м, возраст прогноза и время выпуска не входят в ML-контракт.

Полные запросы: [`turbine_1-48h-request.json`](inference/examples/turbine_1-48h-request.json), [`turbine_2-48h-request.json`](inference/examples/turbine_2-48h-request.json). Для отображения 24 часов всё равно отправляйте 48 записей и показывайте первые 24. Запрос из 24 строк в v1 вернёт 422.

```bash
curl http://127.0.0.1:8001/v1/predict \
  -H 'Content-Type: application/json' \
  --data-binary @inference/examples/turbine_1-48h-request.json
```

При авторизации добавьте `-H "Authorization: Bearer $ML_SERVICE_TOKEN"`. В PowerShell используйте `curl.exe`, одну строку команды и `$env:ML_SERVICE_TOKEN`.

Ответ содержит `schema_version: windpower.output.v1`, `turbine_id`, `weather_model`, `model_version`, `alignment_confirmed` и 48 элементов `records`. В каждой записи — `target_time` и `predicted_normalized_power`. Числа конечные и лежат в [0,1], моменты времени и порядок соответствуют запросу. Контрольные ответы находятся рядом с запросами.

**Как понимать мощность:** 0.5 означает половину нормализованной полной шкалы. Это не автоматически 0.5 МВт или МВт·ч. Для перевода нужны подтверждённые организаторами мощности и определение нормализации. Сумма двух нормализованных значений сама по себе не является мощностью станции в МВт.

### Совместимость погодного источника

Для Open-Meteo используйте `models=jma_gsm`, `hourly=wind_speed_10m,wind_direction_10m,temperature_2m`, `wind_speed_unit=ms`, `temperature_unit=celsius`, `timezone=UTC` и координаты соответствующей турбины. Параметры сетки/downscaling должны соответствовать обучению. Нельзя переименовывать другой источник в JMA или ветер на 100 м в ветер на 10 м. Для смены провайдера нужны обученные и проверенные на нём веса; JSON-схема может остаться прежней при сохранении физических величин.

## 7. Интеграция Django

```dotenv
ML_BACKEND=http
ML_SERVICE_URL=http://127.0.0.1:8001/v1/predict
ML_SERVICE_TOKEN=
```

Этот URL предполагает процессы на одном хосте вне отдельных контейнеров. Минимальный вызов Python:

```python
import os
import httpx

def predict_power(payload):
    token = os.getenv('ML_SERVICE_TOKEN', '')
    headers = {'Authorization': 'Bearer ' + token} if token else {}
    response = httpx.post(os.environ['ML_SERVICE_URL'],
                          json=payload, headers=headers, timeout=30)
    response.raise_for_status()
    result = response.json()
    if result['turbine_id'] != payload['turbine_id'] or len(result['records']) != 48:
        raise ValueError('Unexpected prediction response')
    return result
```

Окружающий код также должен проверять версию схемы, конечность/диапазон чисел, соответствие времени и модель, а затем сохранять/отображать `alignment_confirmed`. Данные о времени выпуска и происхождении прогноза храните в погодном снимке, не добавляйте их неизвестными полями в этот запрос. Для каждой турбины выполняется отдельный вызов; их можно отправлять параллельно.

### Ошибки, повторы, обновление модели

| HTTP / код | Значение | Действие |
|---|---|---|
| 401 / `unauthorized` | Нет токена или он неверный | Исправить авторизацию; не повторять тот же запрос бесконечно |
| 422 / `invalid_request` | Неверные поля или временной ряд | Исправить запрос |
| 422 / `unsupported_turbine` | Загруженные веса не знают ID | Проверить metadata и модель |
| 422 / `weather_model_mismatch` | Неверный погодный источник | Исправить сочетание источника и модели |
| 500 / `invalid_model_output` | Выход модели не прошёл проверку | Сохранить ошибку; не подставлять выдуманную мощность |
| Тайм-аут, ошибка соединения, другие 5xx | Сбой сети, процесса или прокси | Ограниченное число повторов |

Структурированные ошибки содержат `error.code` и `error.message`; ошибки входов также содержат `error.details`. Неожиданные ошибки сервера/прокси могут быть не JSON. Сначала проверяйте HTTP-статус. Отсутствующие или неверные веса не дают сервису запуститься. Модель загружается один раз: после замены перезапустите сервис и учтите новую версию в кэше.

## 8. Модель, данные и фактические результаты

В выбранной модели 2 881 параметр: полносвязные слои 64 → 32 → 1, ReLU внутри, sigmoid на выходе. Признаки получаются только из трёх погодных величин, циклических UTC-часа/дня года и ID турбины. Нормализация вычисляется по обучающей части. Обучение: случайная инициализация, AdamW, MSE, ранняя остановка по validation MAE. Выполнено 28 GPU-эпох, выбран checkpoint эпохи 18.

Совместный датасет содержит 96 900 строк, соответствующих 48 450 парам «турбина–час» с двумя архивными смещениями на каждую. Для часовой цели нужны шесть корректных десятиминутных измерений. Пропуски и неоднозначные часы не выдумываются. Для турбины 1 есть 23 666 полных часов, для турбины 2 — 24 784. Аудит и хеши: [`reports/dataset_assembly_both.json`](reports/dataset_assembly_both.json).

| Период UTC | Назначение |
|---|---|
| До октября 2025 | Обучение весов и расчёт нормализации |
| Октябрь–декабрь 2025 | Выбор checkpoint и модели |
| Январь 2026 | Оценка |
| Февраль 2026 | Конкурсный период; нет предоставленных целей для оценки |

Все архивные варианты одного часа остаются в одной временной выборке. Январь содержит 2 956 примеров, но только 739 различных целевых часов на турбину; копии по смещениям и соседние часы коррелируют.

| Январская метрика | Обе турбины | Турбина 1 | Турбина 2 |
|---|---:|---:|---:|
| MAE | 0.178525 | 0.173897 | 0.183153 |
| RMSE | 0.238635 | 0.232772 | 0.244357 |
| Bias: прогноз минус факт | +0.066447 | +0.059136 | +0.073758 |

Ошибки выражены в долях нормализованной полной шкалы; это не MAPE и не «процент точности». Совместный MAE на 29,1% ниже эмпирической ветровой кривой (0.251898). MAE постоянного прогноза — 0.302035.

### Почему оставлена эта модель

В [эксперименте](docs/MODEL_COMPARISON.md) проверялись другие функции потерь, более крупная сеть, CatBoost, отдельные модели турбин и ансамбли. MAE-ансамбль, выбранный по validation, снизил январский MAE до 0.166403, но ухудшил RMSE до 0.245725. По решению пользователя оставлена исходная MSE-модель с предпочтением меньшего вклада крупных ошибок. RMSE сильнее штрафует большие отклонения, но не гарантирует, что каждый экстремальный прогноз лучше.

Контрольная MSE-модель на CPU имела немного меньший январский RMSE (0.235943), но худший MAE на validation 2025 года. Релиз не заменялся по одному результату января. Январь уже просматривался в ходе разработки и не является полностью слепым внешним тестом. Точность на феврале и гарантированное улучшение в будущем не заявляются.

## 9. Создание следующей модели

Используйте отдельную точку входа и документацию [`training_toolkit/`](training_toolkit/README.ru.md). Там описаны архивы, обе CSV, часовой пояс, обучение CPU/GPU, Brev, сравнения, проверка и выпуск. Доступ к исходным данным нужен для переобучения, но не для инференса.

Сервис использует `requirements-runtime.txt`. Обучение требует extra `train`, сравнения — также `benchmark`. При обычной установке сервиса они не устанавливаются. Новые кандидаты сохраняйте в новые папки, не перезаписывая выбранную модель автоматически.

## 10. Проверки и устранение проблем

Регрессионные тесты разработчика:

```bash
python -m pip install -e '.[train,test]'
python -m pytest -q
```

Эта команда добавляет PyTorch для небольших учебных фикстур. Сервис и HTTP smoke test его не требуют. Тесты проверяют входные ошибки, временное разделение, экспорт, обе реальные турбины и контроллеры. GitHub Actions настроен, но успешные локальные тесты не доказывают успешный запуск hosted CI; проверяйте фактический статус в GitHub.

| Симптом | Что проверить |
|---|---|
| `ModuleNotFoundError: windpower` | Установлен ли корневой пакет тем Python, которым запускается сервис. |
| Ошибка provisional/alignment | Явно разрешите provisional; не правьте metadata для ложного подтверждения. |
| Не найдены веса | Используйте запускатель или существующий `MODEL_PATH`; проверьте клонирование весов. |
| Порт занят | Остановите старый процесс либо укажите `--port 8002` и измените URL клиента. |
| 422 | Названия полей, числовые типы, 48 целых UTC-часов, источник, ID турбины. |
| 401 | Одинаковый токен и префикс заголовка `Bearer `. |
| Контейнер не видит ML | Адрес сервиса в сети, а не localhost контейнера клиента. |
| Старый endpoint возвращает 503 | Используйте `/v1/predict`; получение погоды там не настроено. |
| Замена весов ничего не изменила | Перезапустите сервис. |
| Плохие прогнозы | Сначала проверьте источник, единицы, координаты и привязку времени. Нельзя заменять прогноз фактической будущей погодой. |

Порядок приёмки: клонировать, установить только runtime, запустить, получить metadata для двух турбин/JMA, пройти контрольные запросы, затем отправить по одному реальному погодному снимку из Django и проверить сохранение, отображение и ошибки. Ветка другого разработчика этим релизом не изменяется.
