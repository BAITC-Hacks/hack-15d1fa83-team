# ARYS / Wind Intelligence

Два модуля команды **Арыс** для HackAlem: Django-портал прогнозирования выработки ВЭС и независимый модуль архивных прогнозов погоды. Фронтенд — нативные HTML, CSS, JavaScript и SVG, без фреймворков и сборщика. ML-обучение и inference принадлежат отдельному разработчику; здесь реализован HTTP-контракт и явно обозначенная демонстрационная заглушка.

## Быстрый запуск

Python 3.12+, Git. Команды выполняются в корне этого репозитория:

```bash
# Только если .venv ещё не существует (не пересоздавайте работающую среду):
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux / macOS:
# source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Откройте http://127.0.0.1:8000. Нажмите «Построить прогноз», чтобы пройти полный цикл без внешних сервисов. По умолчанию live: Django сам выбирает текущее время. Для replay выберите исторический момент решения и начало горизонта; время выпуска пользователь не вводит. Все даты в UI — UTC, не локальное время браузера. `seed_demo` добавляет две реальные точки из ссылок задания, не перезаписывая существующие настройки:

| ID | Широта | Долгота |
| --- | --- | --- |
| turbine_1 | 43.645150 | 78.535604 |
| turbine_2 | 43.643198 | 78.538828 |

Кнопки разделов работают: прогноз, таблица погоды, история, описание интеграции. Слайдер под графиком показывает каждый из 48 часов. CSV и JSON выгружают текущий сохранённый результат; ошибки сохраняются в истории. Обновление создаёт новый запуск и пересчитывает мощность, если изменился снимок или версия загруженной ML-модели. UI показывает alignment_confirmed, выбор 24/48 часов влияет только на отображение.

## Режимы данных — не перепутать

1. **Демонстрационные данные**: синтетическая погода. По умолчанию `ML_BACKEND=demo`: аналитическая кривая мощности для проверки контракта, не обученная ML-модель. Результаты имеют `is_demo=true`, заметную маркировку в UI и CSV. Никакие метрики качества не выдумываются.
2. **Open-Meteo / JMA GSM**: в live — текущий прогноз; в replay — архивные значения Previous Runs API. Используются ветер на 10 м и температура на 2 м, без замены источника. Ни ERA5, ни фактическая погода, ни склеенный Historical Forecast API не используются. Выбираются фиксированные заблаговременности 1–7 суток с дополнительным запасом 8 часов на публикацию. Это полезный рабочий источник для подготовки данных, **но точное время выпуска/публикации API не предоставляет**: метаданные обозначены `estimated_fixed_lead`. Подробнее — [погодный модуль](docs/WEATHER_ARCHIVE.md). Предыдущая проверка другого источника не подтверждает наличие JMA GSM; наличие переменных зависит от модели и периода.
3. **Импортированные выпуски**: точный `issued_at` и `available_at`, модель и URL первичного архива предоставляются владельцем данных. Система выбирает последний выпуск, доступный на `as_of` и полностью покрывающий 48 часов. Это режим для строгого воспроизведения условий хакатона; достоверность времени публикации подтверждает источник, а не программа.

Даже при реальной погоде результат мощности остаётся демонстрационным, пока не подключён внешний ML. При ошибке внешнего сервиса нет скрытого перехода на демо.

## Интеграция с разработчиком ML

Начните с [дизайн-документа и контракта](docs/ML_INTEGRATION.md). Также доступны [OpenAPI](docs/openapi.json), [схема ML-запроса](docs/ml-input.schema.json), [схема ML-ответа](docs/ml-output.schema.json) и полные [примеры из 48 часов](docs/examples/).

PowerShell:

```powershell
$env:ML_BACKEND = 'http'
$env:ML_SERVICE_URL = 'http://127.0.0.1:8001/v1/predict'
$env:ML_SERVICE_TOKEN = 'shared-secret-if-required'
$env:API_TOKEN = 'local-development-api-token'
python manage.py runserver
```

На Linux используйте `export NAME=value`. `.env.example` — справочник переменных, файл `.env` автоматически не загружается. Перезапустите сервер после изменения переменных. ML_SERVICE_TOKEN — общий токен сервисов, не NVIDIA key; если на ML он не настроен, оставьте пустым. Ветка GitHub не является API — нужен URL запущенного ML-сервиса. Реальный URL и JSON metadata пока не предоставлены: ожидаемая структура описана в дизайн-документе.

Для отдельной проверки интеграции без настоящей модели: `python tools/mock_ml_service.py`, затем запустите Django с `ML_BACKEND=http`. По умолчанию он поддерживает только turbine_2, выдаёт metadata и alignment_confirmed=false. Этот сервис возвращает тестовые значения и версию `mock-contract-v2`; он нужен только для разработки.

## API

Все URL завершаются `/`, кроме CSV. JSON, временные метки ISO 8601 со смещением, нормализованные к UTC. Не передавайте локальное время без timezone.

| Метод | URL | Назначение |
| --- | --- | --- |
| GET | `/api/v1/health/` | Статус Django и выбранный ML-адаптер (не проверка доступности ML) |
| GET | `/api/v1/ml/metadata/` | Возможности загруженного ML-артефакта |
| GET | `/api/v1/turbines/` | Турбины и координаты |
| POST | `/api/v1/weather/forecast/` | Получить 48 часов погоды |
| GET | `/api/v1/weather/snapshots/{id}/` | Неизменяемый погодный снимок |
| POST | `/api/v1/weather/import/` | Импорт архивного выпуска |
| POST / GET | `/api/v1/forecasts/` | Создать прогноз / последние 100 запусков |
| GET | `/api/v1/forecasts/{id}/` | Результат, погода, журнал и ошибки |
| POST | `/api/v1/forecasts/{id}/refresh/` | Повторно получить погоду и пересчитать изменившийся ввод |
| GET | `/api/v1/forecasts/{id}/ml-input/` | Точный запрос внешнему ML |
| GET | `/api/v1/forecasts/{id}/export.csv` | 48 прогнозов с версией и демо-маркером |

Тело live-запроса: `{"mode":"live","turbine_id":"turbine_2","provider":"open_meteo","weather_model":"jma_gsm"}`. `as_of` и `start_time` в live запрещены — их выбирает Django.

Тело исторического запроса прогноза или погоды:

```json
{
  "mode": "replay",
  "turbine_id": "turbine_2",
  "as_of": "2026-01-31T18:00:00Z",
  "start_time": "2026-02-01T00:00:00Z",
  "provider": "open_meteo",
  "weather_model": "jma_gsm"
}
```

Server-to-server запросы используют `Authorization: Bearer <API_TOKEN>`. В браузере используется CSRF-токен. В development чтение открыто на localhost; при `DJANGO_DEBUG=0` и UI, и API требуют авторизацию. Для входа через браузер: `python manage.py createsuperuser`, затем `/accounts/login/`. В админке можно менять турбины; снимки и результаты только читаются.

## Последовательное воспроизведение и обновления

```bash
# Офлайн smoke test одного дня (48 часов; результат помечен demo)
python manage.py backtest --provider demo --start 2026-02-01 --end 2026-02-01 --output output/demo.csv
# Весь тестовый период, точные заранее импортированные выпуски
python manage.py backtest --provider archive --weather-model jma_gsm --turbine turbine_1
# Один проход агента по последним 20 различным окнам
python manage.py refresh_forecasts --limit 20
# Импорт из документированного формата
python manage.py import_weather path/to/archived-run.json
```

Backtest для каждого дня рассчитывает 48 часов с `as_of` в 18:00 UTC предыдущего дня. Перекрывающиеся горизонты сохраняются отдельно, не усредняются и не смешиваются. Выход за 28 февраля включён как часть 48-часового горизонта; фильтрацию периода оценки делает разработчик ML. Существующий CSV не перезаписывается. При ошибке процесс останавливается, сохраняя предыдущие строки и журнал ошибки. Повторите для второй турбины с другим выходным файлом.

`refresh_forecasts` выполняет один проход, а не запускает вечный процесс. Его можно запускать по расписанию средствами сервера. Планировщик на компьютере пользователя автоматически не устанавливается. Неизменившийся снимок повторно не вызывает ML; новая версия из GET /v1/metadata автоматически инвалидирует кэш предсказаний.

## Архитектура

```text
Browser (HTML/CSS/JS)
    -> forecasting: request -> weather -> validate -> external ML -> validate -> analysis
                                  |
                         weather_archive
                        /       |         \
                 Previous Runs  imports    demo
                                  |
                     SQLite immutable snapshots + forecast trace
```

`forecasting/` — оркестрация, адаптер ML, результат и UI/API; `weather_archive/` — источники, импорт, выбор выпуска и снимки; `common/` — контракты, ошибки и API-доступ; `templates/`, `static/` — фронтенд; `tests/` — проверки. Модуль погоды можно использовать отдельно через HTTP без обращения к ML. Агент — детерминированный state machine с журналом инструментальных этапов, не LLM и не обучающая система.

## Проверки

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

Проверяются полный цикл и экспорт, CSRF/token-доступ, запрет утечки будущего, время и единицы, архивные выпуски, кэш, изменение погоды, ML-контракт и тайм-ауты. Unit-тесты не обращаются к внешней сети. GitHub Actions запускает проверки при push/PR.

## Ограничения и развёртывание

SQLite и синхронный вызов с тайм-аутом 30 секунд подходят для хакатона и одного процесса. Для нагрузки нужны PostgreSQL, очередь задач и worker; прерванный процесс может оставить запуск `running`. Автоматических бесконечных retries нет. Обучение, метрики по фактической мощности, вероятностные интервалы и агрегирование в МВт не реализованы: нет модели, целевых рядов и подтверждённой номинальной мощности. Используется безразмерная мощность [0,1].

Для production установите `DJANGO_DEBUG=0`, уникальный `DJANGO_SECRET_KEY`, `API_TOKEN`, точный `DJANGO_ALLOWED_HOSTS`; настройте HTTPS, WSGI-сервер и отдачу static (`python manage.py collectstatic`). Не публикуйте `runserver` в интернет. `.env`, база и служебные файлы не попадают в Git. Google Fonts имеет системный fallback, все функции работают без шрифта из сети. Дизайн вдохновлён типографикой и контрастом edu.astanahub.com, без копирования его бренда или изображений.
